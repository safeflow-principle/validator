# Security policy

Do not place credentials, production data, private annotations, or sensitive vulnerability details in a public issue.

If this repository's **Security** tab offers **Report a vulnerability**, use that private GitHub channel. No separate private vulnerability-reporting address has been verified for this release. If the private form is unavailable, open a non-sensitive issue asking the maintainers to establish a private contact channel; omit exploit details and secrets.

When reporting, identify the affected version, local or cloud mode, expected security boundary, reproduction prerequisites, and whether production data may be at risk. Do not test against infrastructure or data you do not own or have explicit permission to assess.

Supported security fixes target the latest published release. Research software is provided without warranty under Apache-2.0.
